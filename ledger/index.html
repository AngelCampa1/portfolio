The ledger

Every figure on this site, added up. The product pages carry the detail and the reasoning, and the scale of it is hard to see spread across 17 of them.

I measured none of this. Each number was recorded by the repository it came from, and traces back to the document that produced it. All I added was arithmetic, which sounds like the easy part. The repositories did not all count the same way.

The shape of it

17 products across 5 eras. 16 of them sit inside a closed build period of 430 days, which is the span the headline on the home page counts. The core sample beside it runs past that, to today, because one era has not closed. 8 were sunset and 7 retired. The last 2 carry no status.

Those 17 pages hold 134 recorded figures and 64 screenshots. Every figure carries a source and the date it was measured. The content schema requires both, so a number without provenance fails the build rather than reaching a page.

What adds up

Four quantities turn up often enough, and were counted closely enough alike, to be worth summing. The repositories record plenty else, and the rest of it stayed on the product pages. A quantity counted three different ways in three repositories gives you a total that reads like a fact and behaves like an average of unlike things.

How these totals were made

The line totals sum measurements taken under different rules. Those counts came from separate scripts written months apart. CapVeri counted six file extensions and excluded generated output. Gavelhouse counted every tracked file with tests inside the figure. SkillLedger counted C# and left its web client's TypeScript out entirely. The last column of each table carries what each one covered. Read the total as one uniform measurement and you have misread it.

The test case column mixes runs with static counts. Where a repository recorded a real run, the figure is tests that passed. Where it recorded only a count of the tests sitting in the tree, that is the figure, and in two cases the suite was never run for the snapshot at all. Gavelhouse's is explicitly approximate: it counts call sites, which undercounts table-driven suites. Read the column as a count of tests that exist, not of tests seen to pass.

Every commit figure comes from a private history. The published snapshots are single squashed commits, so no public repository can confirm any of these numbers. They are here because they are what the repositories recorded, not because a reader can check them. That is the one place on this page where the provenance link runs out.

The gate on this page

Every number in the tables is a restatement of a number already printed on a product page, and the build checks that it still matches the sentence it was taken from. Edit one without the other and the build fails, naming the figure and the sentence it no longer agrees with. The totals read from the same claims the product pages make.
